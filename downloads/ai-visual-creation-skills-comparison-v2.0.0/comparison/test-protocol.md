# 用户验证流程

## 1. 预先固定任务

选择P组和模式：text / image / video / code。保存同一份需求和同一份参考文件，记录其哈希。不要测试中途只给一组补充说明。先定输出格数、时长、画幅、模型、参数和次数。

使用独立会话，或明确清空上一组规则；每组仅加载对应的一个Skill。相同助手模型与工具版本，禁用其他自动触发的Skill。若无法隔离，写入实验限制。

## 2. 区分测试层级

- 文本层：两组生成导演提示词，比较原意、引用、可执行性、矛盾和缺失。不给视频质量打分。
- 初次输出层：各组一次初次生成，不加返修。比较生成图或视频。
- 返修层：从各自初稿开始，事先规定相同的返修次数和可使用信息，计入调用次数与人工指导。可以比较完整流程，但不与初次输出混淆。

P2建议四格，统一只生成1张初稿；另开返修轮最多1次。若要初步观察稳定性，按相同预算重复至少3轮，保留全部结果。3轮仍不足以推断普遍优越。

模型支持seed时记录seed并对两组采用相同设置。即使seed一致，也不代表不同提示词结果严格可控。没有seed接口时不要填虚构值，注明未提供；轮换A/B执行顺序，减小时间因素影响。

## 3. 处理原版不兼容

原始seedance-director可能要求特殊writing block、具体模型能力或引用方式；CTX原版含逐步确认。先按原规则执行。宿主不支持时记录具体不兼容，不能默默替换。

如需适配，先定义共同协议，再重复运行两组，另命名adapter版本。只转换接口与文件引用等必要部分；改变角色、事件数、限制项或推理流程属于语义改编，必须记录并另算。

缺少图像或视频工具时标记未执行；没有视频只做图片或文本。不能为了填满结果表，把生成计划当成输出。

## 4. 留存

每次保存：测试题、Skill文件哈希、参考图、实际生成提示词、宿主/模型/版本、可见参数、所有输出、返修文字、耗时和已知费用。未知消耗填unknown，不推测。

脚本 scripts/record_run.py 可记录文件哈希；它不会调用模型，也不会给质量结论。结果表见 results-template.csv，所有预填项都是not-run。

## 5. 同一标准验收

图像用“符合/部分符合/不符合/无法判断”检查：人物脸、服装左右、道具数量与形状、手部握持、地标与方向、动作含义、每格信息、局部修订附带变化。

视频另检查：动作连续、接触/遮挡、身份随时间变化、曝光闪烁、切镜与运镜、实际时长、声音与口型。图片不能回答这些项目。

可以将输出随机命名X/Y后盲评，再揭晓路线。报告每轮结果，不只展示最佳样本。看不清的项目写无法判断，不写通过。

## 6. 结论格式

本任务/本模型/本次预算下，A与B各完成什么；哪些问题反复出现；额外花了多少次生成；哪些仍未测。没有实测就不写“优化有效”，只有个别样本就不写“稳定优于”。
