# 指令 07 · 提示词去重合并器（网页端单文件 · 今晚派这个）

> 会话类型：纯前端单文件应用｜**不需要本地文件、不需要 GPU、不需要任何 API Key**
> 目标：把 22 个主题、上千条提示词里的**重复/近似重复**找出来，给出可人工裁定的合并方案，并导出干净的合并结果。
> 为什么值得做：库里风格词、构图词、光影词在 17 个主题之间反复出现；现在没人知道哪条是冗余的，导致"新建条目其实早有"、"改一条忘了另一条"。

---

## 0. 一句话需求

做一个**单文件 HTML**：拖入 `prompts.json` → 自动归一化 + 算相似度 + 聚类 → 逐簇人工裁定"保留哪条、并入哪条、补入哪些片段" → 导出**合并后的 JSON + 合并台账 md + 需人工裁定的冲突清单**。

**不做的事**：不联网、不调模型、不要后端、不要账号。相似度**全部在浏览器里用确定性算法算**，可复算、可复核。

---

## 1. 硬技术要求（这几条决定能不能跑起来）

1. **必须 `file://` 双击可用**：**禁止** `fetch()`、**禁止** `type="module"`、**禁止**任何 CDN/外链。数据只来自：内嵌常量 / `<input type="file">` / `localStorage`。
2. **零依赖**：不能用分词库、不能用 lodash、不能用 diff 库——**自己写**。字符 n-gram 与短语切分都不需要词表。
3. **单文件 ≤ 350 KB**，vanilla JS，无构建步骤。
4. **中文无空格**，所以**禁止**用空格分词算法。见第 3 节。
5. **性能护栏**：n 条两两比较是 O(n²)，2000 条 = 约 200 万次。必做：
   - n > 1200 时**强制提示**"建议按主题分桶"，并提供"按 topic 分桶跑"按钮；
   - 计算期间每 200ms 让出主线程（`setTimeout(0)` 分片）并显示**已处理 / 总数 + 已等待秒数**，禁止界面假死无提示。

## 3. 算法规格（必须按这个实现，我要能复算）

### 3.1 归一化（默认全开，界面上给开关）

1. 全角转半角；中文标点统一（`，。、；：！？（）【】`）；
2. 连续空白折叠成单个空格；去首尾空白；
3. 英文转小写；
4. 可选：去**噪声前缀/后缀**词表（默认表，界面可编辑）：
   `请基于` `请生成` `生成一张` `一张` `图片` `画面` `要求` `注意` `必须` `输出前检查` `检查` `确保` `尽量`
   → **这一步必须有开关**，因为"要求/检查"类词在所有指令里都出现，不删会让全部条目都显得相似（这是本任务最大的假阳性来源）。

### 3.2 相似度（**已校准，别自己换公式**）

⚠️ 这一节是**实测校准过的**：我原本想用"短语 Jaccard + 3-gram 余弦、阈值 0.82"，拿 8 条样例实算后发现**最高的近似重复只有 0.40，全部漏检**。原因是中文按「，」切出来的整句几乎互不相同，短语 Jaccard 对近似改写没有区分度。所以改用下面这套：

- **LCS 相似度（权重 0.6）**：归一化文本做字符级最长公共子序列，`sim = 2×LCS长度 / (lenA + lenB)`。对"同义改写/调序/加字"最灵敏。
- **字符 2-gram 余弦（权重 0.4）**：取所有长度 2 的字符片段做词频向量，算余弦。对"调序"容忍，弥补 LCS 的顺序敏感。
- **最终分 = 0.6 × LCS + 0.4 × 2gram余弦**；两个权重给输入框，默认 0.6 / 0.4。
- **短串护栏（必须有）**：任一条归一化后 **< 12 字** → 不做模糊，**只判"归一化后完全相等"**（相等=1.0，否则=0.0）。原因：短串的 LCS 比值天然虚高（"侧逆光" vs "顶光" 能算到 0.5 以上），不设护栏一定假阳性。
- **预处理剪枝**：归一化后长度比 < 0.4 或 > 2.5 的两条**直接跳过**（省掉大部分无谓比较）。
- 短语级 Jaccard **可以留着当一列"诊断值"显示在簇内**（帮助人判断），但**不参与阈值判定**。

### 3.3 聚类

- 并查集（union-find）；`sim ≥ 阈值` 就 union；**阈值默认 0.50**，滑块 0.30–0.95，拖动后**实时重算**（大 n 时先提示预计秒数再算）
- 单条成簇不显示；只显示成员 ≥ 2 的簇，按簇内最高相似度降序
- **实测区分度（同一套样例）**：真重复落在 **0.632 / 0.775 / 0.781**，无关对最高只到 **0.231**。0.50 这个默认值就是按这组数据定的，上下留了余量。

### 3.4 簇内展示

- 每簇：成员卡片（ID / 标题 / 主题 / 字符数 / prompt 全文可折叠）
- 成员 ≤ 8 时显示两两相似度矩阵
- **差异高亮**：簇内两两做**字符级最长公共子序列 diff**（自己写，LCS 就够），高亮"仅 A 有 / 仅 B 有"的片段
- 默认推荐"保留最长的那条"，但必须可手动改

## 3.5 数据里已经存在的两个标签（必须处理，否则必然假阳性）

真实导出数据（403 条）里有两个 tag，你的工具必须认：

| tag | 含义 | 工具必须怎么做 |
|---|---|---|
| `模板生成` | 该条不是原文，而是用固定模板套色卡/品牌色生成的（仅 07 配色库、11 品牌色库，共 13 条） | **默认排除出配对池**，单独一栏列出。它们之间只差一个颜色名/色值，参与配对会 100% 互相判重——我在本地实测过：8 条配色直接自动成一簇，是构造性假阳性 |
| `片段` | 关键词积木（如"高马尾 + 电竞耳机 + 未来感少女 + 科技感"，150 条），不是完整提示词 | 参与配对，但簇内必须**标注它是片段**；合并时**优先保留完整提示词那条**，不许把片段选成主条 |

界面上要能一键切换"排除 `模板生成`"（默认开）。报告里写明本次排除了几条。

## 4. 人工裁定与合并（这是核心）

每簇给出四个动作：

| 动作 | 含义 | 必须记录 |
|---|---|---|
| 保留 | 选一条作为主条 | 被选 ID |
| 并入 | 其余标记并入主条（默认全选） | 每条并入的 ID + 它与主条的相似度 |
| 补入片段 | 从被并条目里**手动勾选**"主条缺失的片段"追加到主条 | 勾了哪些片段（原文） |
| 不合并 | 整簇标记"看着像但实际不同"，附一句话原因 | 原因文本 |

**合并产出规则**：
- 主条 `prompt` = 原文 + 勾选的补入片段（追加顺序按勾选顺序，用「，」连接）
- 主条 `tags` = 并集去重；`slots` = 并集，**同 key 不同 default → 不算冲突合并，进冲突清单**
- 主条加 `merged_from: [被并 ID…]`、`merge_sim: [对应相似度…]`（**不许省**，这是台账依据）

**进度防丢**：所有裁定结果写 `localStorage`，刷新不丢；写入失败（超配额）→ **常驻红色错误**，并提示"先导出一次再继续"。

---

## 5. 导出三件套

1. `prompts.dedup.json` —— 合并后的完整数据（schema 不变，只多 `merged_from` / `merge_sim`）
2. `merge_report.md` —— 一簇一节：主条 ID / 并入 ID 列表 / 相似度 / 补入片段 / 丢弃的条目及原因 / 未合并簇及原因
3. `conflicts.csv` —— 需人工裁定的项：`类型,条目A,条目B,相似度,冲突内容,建议`（类型含：槽位冲突、**边界对**（相似度落在阈值 ±0.08 之间，默认 0.42–0.58）、跨主题高度相似对）

报告里必须带**参数快照**：阈值、两个权重、噪声词表版本、条目总数、比较次数——少了这行，我无法复核你的结果。

## 附：数据从哪来（不用你操心）

用户侧由 Hermes 本地导出真实 `prompts.json`（22 个主题），你只需要保证**导入任意合法 JSON 都能跑**。
**你的验收标准 = 内置 8 条样例把 3 组重复抓准 + 导入真实数据不崩**，不是"数据完整"。
真实数据里同一主题内的重复最多，跨主题的"看起来像但语义不同"（如"电影感"风格 vs "电影感运镜"）会被阈值误抓——所以 `conflicts.csv` 里必须包含"跨主题高度相似对"，让人来判。
