## 实验设计与限制

前四组使用相同的原始参考图；AB05刻意只让B实际附图。前三组的实际提示词只替换指定变量；透明组只改是否保留投影，且两组都设置 `transparent_background=true`。Remotion组只改props中的 `illustration`，其余文字、帧数、动画代码、画幅和渲染设置相同。

工具是内置 `image_gen.imagegen`。每个条件只调用一次；没有固定seed，工具也没有暴露具体模型版本。即使设置只改一个变量，输出仍可能连带变化。**这是一轮探索性成对样例，不是随机重复试验、模型基准或因果提升证明。** A/B不默认意味着B更好。

这些提示词从现有模板按测试目的改编，完整实际执行文本单独保存；不冒充原模板逐字执行。具体配置见 [plan.json](../artifacts/ab-2026-10-23/plan.json)，调用起止时间与生成文件位置见 [invocations.json](../artifacts/ab-2026-10-23/invocations.json)。时间是调用墙钟时间，包含排队与工具开销，不是纯模型推理时间。

## 关键发现

### 电商：保留参考有用，但仍要核对真实商品

AB01的A保持近白底，B变为浅暖灰。左上角同一采样区域均值分别约RGB(254,254,254)和(229,223,217)，支持“背景色确实变化”的观察；不把它当整张图片颜色精度认证。杯盖光泽与金环反射也略有变化。

本次参考本身是虚构商品生成图，不是真实SKU实拍，无法验证真实商品保真。白底主图和创意背景图各有用途，不做统一优胜排名。

### 影视：写“只改光线”不能确保其他内容不变

AB02的B出现了参考中没有的明显日出亮点，同时地面反射更强。它可以用来探索风格，但没有满足连续镜头中严格保持时间/太阳状态/曝光的要求。输入的6500K/3200K是提示目标，不能通过生成图片证明物理色温达标。

建议把光线风格探索和定稿连续性分开；需要精确保持结构时使用受控调色或受限编辑流程，而不是仅增加形容词。

### 透明：alpha已验证，预览不能代替正确合成

AB04-A/B都为RGBA PNG，完全透明像素分别约 **73.65% / 77.09%**，不是画棋盘格冒充透明。A保留投影，B移除投影。

初步观察透明预览时，我把部分浅色毛刺过早判成了成品缺陷。复查原PNG后发现，例如A的(716,79)、B的(556,70)像素为RGBA(255,255,255,1)，alpha仅1/255；浏览器正确合成到深底时，这些白点近乎不可见。**不能把预览异常直接等同真实成品白边。**

最终判定改为“真实透明已验证，边缘按目标背景原始像素人工复核”，不再认定本轮已证实生产失败。原图没有修改；[修订记录](../artifacts/ab-2026-10-23/review-revision.json)保留旧结论、原因与像素证据，初评文件明确标为superseded。目标背景100%检查仍有必要，不能因为有alpha就自动批准商品素材。

### 角色：附图改善了这个样例，但侧面不能证明正脸身份

AB05-A虽然有四种视图，却输出为四列，违反2×2要求。B符合2×2，兜帽、橙夹克、袋型更接近给定关键帧。

原参考主要是侧面中远景，因此B的正脸仍是模型补全，不能认定为“角色身份已锁死”。应先有清晰正脸和服装/道具定稿，再进入多镜头生产；模型换布局是否稳定，还需重复样本。

### Remotion：真实素材接入与品牌色仍是两件事

AB03的A/B插画进入同一个 `KineticWords` 组件，实际输出 [A视频](../artifacts/ab-2026-10-23/remotion-A.mp4) 与 [B视频](../artifacts/ab-2026-10-23/remotion-B.mp4)：均为1080×1920、30fps、6秒、180帧、H.264、静音。动画和文字不变，只换允许的本地图片文件。

原组件标题强调色仍为橙色，因此B的青绿插画不代表整套品牌色已经统一。精确品牌色更适合由矢量或代码图层控制。技术证据见 [video-results.json](../artifacts/ab-2026-10-23/video-results.json)。这不是AI视频模型的人物动作、音频或跨镜头连续性测试。

## 覆盖情况：哪些测了，哪些没测

- 原创50条模板中，本轮执行了5类图片配方的改编A/B，以及REM-01对应组件的素材A/B渲染；其他模板没有因此被标为通过。
- 8个原创Skill中，按 `ecommerce-image-director`、`film-asset-bible`、`remotion-insert-designer` 的视觉相关步骤执行；不是这3个Skill完整流程全部通过，更不是8个全部端到端通过。
- 没有测试AI视频供应商、TTS、完整口播、5–10分钟成片、真实SKU保真或多次随机稳定性。
- 原型交互已有初版浏览器证据，本轮没有因生图就宣称画布交互通过A/B用户研究。

逐项状态见 [coverage.json](../artifacts/ab-2026-10-23/coverage.json)。视觉审查由助手完成，不冒充独立人工评审。

## 本轮回写的改进

1. 给透明图片模板与电商Skill补充：读取实际alpha，并在黑/白/棋盘格背景检查白边毛刺。
2. 给角色多视图模板与资产Skill补充：验证布局，不以“四个视图齐全”代替排版正确；侧面参考不能替代清晰正脸。
3. Remotion关键词组件增加受白名单限制的本地 `illustration` 参数，方便同组件素材A/B，禁止任意路径。

原始测试图没有修改；更新的是检查要求与可复用组件。

## Hermes验收

先检出本次更新后的main，不能用旧 `bc7a046` 去验收新增文件。

```bash
# 完整仓库文件与初版交付验证；标准库 + ffprobe
python scripts/verify_delivery.py

# 本轮独立验证：Pillow + ffprobe
python scripts/verify_ab_tests.py
```

需要重新检查画廊交互或生成对照PDF时，可运行 `python scripts/test_ab_gallery.py`，依赖Playwright及Chrome/Chromium。不要因为缺依赖而把未执行写成通过。工具依赖在 `requirements-tools.txt`。

注意：`verify_ab_tests.py`通过表示设置、文件、哈希、alpha和视频技术证据一致；它会同时显示素材的部分通过/待复核状态，不会把这些质量问题清零。重编码后的文件字节可能变化，原SHA只用于本次原件核对；不要重写基线来掩盖差异。

浏览器打开下载后的 `artifacts/ab-2026-10-23/index.html`，在三种底色检查透明边缘，并用同步定位按钮比较视频同一时间。GitHub直接看该目录README即可并排查看原图。

若浏览器策略禁止file协议，可在仓库根目录运行 `python scripts/local_media_server.py`，再通过该本机服务打开画廊。服务支持MP4字节范围请求；普通不支持HTTP Range的静态服务可能只能从头播放，无法定位3秒。服务仅绑定本机回环，不对外发布。
