MiniMaxH3SCD composes H3's 50 blocks into encoder 0-29 plus decoder
{0,1} u {45-49}: 37 layer instances from a 50-block model, which is why the
originally planned identity test is impossible and is replaced by weight parity,
prefix parity and independence.

Two choices worth stating. The composition CONSUMES the base — tail blocks are
moved into the decoder, not copied, because a spare copy of five 5376-wide blocks
does not fit beside the base on a 24 GB card. And encode() captures the per-block
arguments from the base's own first block through a hook rather than
re-implementing its ~100-line preamble, which would drift the way Phase 0's
transcribed numbers drifted from their JSON.

Tests run a hidden-64 stand-in on CPU: 9 cases, 1.2 s, no weights, no GPU.
Prefix parity failed first for a real reason — the base draws fresh randn silence
audio rows per call, so two forwards with identical arguments pack different
sequences. Both non-trivial invariants were mutation-tested; notably weight parity
still passes when the deepcopy is removed, which is why aliases() compares
data_ptr rather than state_dict.

check_findings.py now reads the split constants with ast and fails if the decoder
drops a block the ledger calls load-bearing. CI cannot import fizgig, so it lints
and compiles these; the test result is recorded in the design doc.

…costs

Phase 0's frame-causal mask restricts only video queries, so text and audio
rows keep absorbing every frame and hand the future back to video at the next
block. It is causal for one block and not for a stack, which also makes an
encoder KV cache silently wrong. The shipping mask blinds context rows to video
too; test_scd_attention.py pins both the property and the rejected variant's
failure.

Measuring that stricter mask on real weights split two ways. Video survives -
centered cos 0.95-0.97 at the encoder cut, flat at 0.998 through block 25 with
a cliff at 30, which corroborates the 29/30 split from an independent
direction. Audio does not: 0.047 and -0.074, because audio is context under
this mask and therefore video-blind, so the encoder cache carries no AV fusion
and D1's second decoder pass has to create all of it. Raw cosine read 0.98 on
those same rows at common mode 0.996 - the cos-inflation artefact that
manufactured the first probe's headline, recurring in a script written after
the rule against it. Protocol rule 10 now requires centered cos and common mode
to be emitted together.

           [/MiniMax-AI/MiniMax-H3/pull/90/commits/27bdd2d4aafbfafd7cfdfe0dd1765b955008a73e] 27bdd2d

      

    

  

    

      
The strict frame-causal mask makes context rows blind to video, which is what
makes an encoder KV cache actually a cache. Audio sat in that context class by
scope, not by nature — §5 D1 assumed a second bidirectional pass would recover
it. On real weights it does not: the encoder's audio rows come out at centered
cos 0.047 / -0.074 against the bidirectional pass, so the cached prefix holds no
audio-video fusion for that pass to reuse.

So audio is ordered too, on its own 40 Hz spans, read off the packer's rotary
t-axis rather than reconstructed from a rows-per-frame ratio: _video_t_grid's
(1,4,4,4,4)x5/3 spans already make the two clocks commensurate, and pos[:, 0] is
that answer for free. Both modalities causal on a shared axis is still leak-free
— nothing carries the future backward — and audio comes back to 0.445 / 0.339.
Not the bidirectional 0.99, and it cannot be: causal audio genuinely cannot see
future video, so that number is a ceiling, not a target being missed. Video pays
about 0.03 of centered cos, having lost future audio.

The measurement itself was quoting raw cosine, the same artefact protocol rule 10
exists to prevent, in a script written after the rule. Raw cos reported audio
"recovering" to 0.980 at common mode 0.996. Both are emitted now, from
phase0_validate's definitions.

Falling out of the sentinel change (-inf rather than a magic index): the mask
rule is just `k <= q`. Context always visible and context blind to the ordered
rows are the same inequality read from its two ends.

Under the AV clock time order is no longer row order — audio and video interleave
in time while staying in separate slabs of [context | audio | video] — so
encode_chunked cuts chunks by argsort/searchsorted and scatters back. A row-slice
version passes every other test and fails only the AV chunk assertion.

           [/MiniMax-AI/MiniMax-H3/pull/90/commits/aaa2d0bec1786e6a3b875ae1bac4417a31acb69d] aaa2d0b

      

    

  

    

      
…at actually mattered

Tier 1 could not start: the mask was dense, and a bool [S,S] at 768p/15s is
3.8 GB. scd_attention.block_mask builds the same `k_time <= q_time` rule as a
compiled FlexAttention BlockMask, with queries and keys as separate time vectors
because a chunk's queries are the new rows while its keys are the whole cache.
encode_chunked(block=True) selects it; not a default, since a size threshold
means nobody can tell from a call site which attention ran.

Measuring that led to the larger blocker. Thirty encoder blocks hold 840 KiB per
row, so the KV cache the mask feeds is 53 GB at the same size — 14x the mask.
The dense mask was the visible problem and the cache was the real one, which is
roughly the inverse of how the risk register ranked them.

So §8.1's window policy ships too: encode_chunked(window=W) keeps the last W
latent frames and evicts the rest. It evicts rather than copying CastleHill's
reset-and-re-encode-the-overlap — an evicted row keeps the K/V it was computed
with over the full history it saw, a re-encoded overlap row knows strictly less,
and eviction is cheaper. What it gives up is that a chunk boundary is a clean
restart, which matters only if drift accumulates and is Phase 5's to measure.

Unlike everything else in Phase 2 this is an approximation, not a reassociation,
so a full-width window is pinned bit-exact against window=None. On the tiny model
a 2-frame window holds the cache at exactly 53 rows while the sequence grows
191 -> 327 -> 463: §8.1's flat-VRAM claim as an equality.

Two things this got wrong first. The window has to exempt CONTEXT explicitly —
those rows sit at -inf, behind every horizon, so a time-only window drops the
text rows first and the encoder loses its conditioning one chunk in with no shape
change to notice. A row-count floor clears that mutant comfortably; only the exact
count (53 vs 48) catches it. And the first test counted audio as context, which is
true under the video-only clock and false under the shipping AV clock.

Tier 1 runs the untrained SCD graph against stock H3 on NF4 FL2VA weights:
2.93x/3.51x/3.87x at N=8/16/30 for latent_t=12, ceiling 4.39x. The result the
gate did not ask for matters more than the ratio — stock OOMs past ~2s at 768p

Two findings forced changes to the plan rather than following it:

The block mask is the wrong tool for the chunked encoder. Each chunk is a new
(Q, K) shape, so Dynamo hits its recompile limit at chunk 9 and silently falls
back to eager flex_attention, which materializes the full scores matrix — the
exact thing the block mask was adopted to avoid. Chunking had already solved
that problem by bounding Q to one frame. block=False everywhere in the chunked
path; block_mask stays for the single full-sequence pass.

holds one block's KV cache instead of thirty, so the 53GB blocker was a
property of the loop order, not of the encoder. Streaming AR still pays it.

check_findings gained check_tier1, which recomputes each speedup from its parts
rather than trusting the stored value, and bounds cache growth by one frame's
rows rather than demanding equality — the window is denominated in video frames
but audio rows land on their own 40Hz grid, so it jitters by ~20 rows. It also
flagged that the headline row's window never evicted; phase25_tier1_w8.json is
the control that closes it, and shows the windowed encoder marginally faster.

decoder_frame_input / decode_frame build one frame's decoder pass as

sit at different timesteps and the base packs one video timestep per forward,

Three knobs borrowed from the SCD reference implementation, each independent:

- Per-frame sigma. The reference draws a timestep per (batch, frame); v0 drew one
  per clip, which is 7x less sigma coverage for the same encoder pass. Not free
  here as it is there: the base packs a single video timestep per forward, so each
  distinct sigma costs a `preamble`. `Batch.t` now raises rather than returning a
  mean, because `preamble` broadcasts silently and would pack every frame at frame
  0's noise level.

  clean latent, so one pass serves K noise draws. At 30 encoder blocks against 7
  decoder blocks a second draw is ~23% more compute for twice the decoder's
  gradient signal, and it composes with the two-stage backward for free — the
  extra frames accumulate onto the same detached leaf.

- `--decoder-lr-ratio 2.0`, split by adapter name prefix.

A clip-wide sigma still packs exactly once, which keeps `evaluate`'s fixed grid
comparable with v0: step-0 eval reproduces at 2.3863 against v0's 2.3864.
