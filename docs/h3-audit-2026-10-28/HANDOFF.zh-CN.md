## 3. 接手后的第一阶段：只读盘点与方案对齐

- 已用模型文件的准确路径/名称、可取得的revision/hash；后端/节点commit、运行库版本、GPU/显存及启动参数。
- 已有输入素材、原始输出、失败案例、日志及其对应关系。

## 4. 最小验证次序：只选择影响当前用途的项目

后续获准执行生成时，采用下面的顺序。没有对应需求的项目可以不测，并写明原因。

| 优先项 | 最小问题 | 核心观察 | 什么时候值得继续 |
|---|---|---|---|
| 产品/人物身份 | 一个低动态片段能否保留必要外观 | 脸、瓶形、结构、主色、包装字标、手部配饰是否漂移 | 高风险身份资产可用，再增加动作或镜头 |
| 参考音频 | 音色参考是否引入源台词、重复或句首截音 | 同输入有/无参考音频的合法对照；逐字转写、边界听检 | 确实需要声音，且单角色基础可用 |
| 多说话人 | A-B-A能否让A在第三轮恢复自己的声线 | 视觉身份、说话顺序、声线、台词分别检查 | 真实项目有多人对白需求 |
| 两段接缝 | 两个片段能否组成可用连续段 | 身份、物体、空间、光色、运动、音频和语义交接 | 单片通过，再进入30秒或60秒 |

先每臂一个样本定位流程；需要判断稳定性时再选定多个seed做配对。所有臂保持其余条件一致。三次样本也不足以证明普遍稳定，应报告“通过数/实际尝试数”及局限。

声音对照须避免混淆：断开音频后清理无效Audio引用，才是合法的无音频控制；保留悬空标签的版本只能单列为提示词诊断。多角色默认遵循官方稳定Sx编号；社区“每轮换新ID并复制音频槽”只能作为明确标注的额外实验。

不能同时换权重、关LoRA、改步数和升级后端，再将改善归因一个因素。跨模型fallback、后期叠字、重配音或剪掉爆音均单独记录，不覆盖原生失败。

## 5. 若真实目标是60秒品牌片

先确认以下边界，再决定是否投入：

- 审计快照README声明单次输出4–15秒、24fps、32kHz立体声；本地实现或第三方路线有扩展时另列来源与版本。
- brand-promo-video-generator常规目标15–30秒，包含片段生产与编辑装配；没有给出60秒专用验证保证。
- 60秒属于外层编排实验。素材可用区间、参考文件额度、跨片身份、全局声音与剪辑时长需要单独管理。
- 品牌30fps是规划惯例，H3原生24fps是另一时钟。先按秒对齐；交付转码不等于原生30fps。
- 本地Base与托管Context-IR/Regenerate-2K分开登记；克隆源码不意味着纯本地已具备完整官方2K链路。
- Logo、真实UI、包装和产品证据必须用可核对资产；生成的近似图不能替代真实来源。

建议门槛：**一个高风险镜头 → 一对接缝 → 30秒装配 → 60秒。** 上一阶段失败未解释时，不增加全片复杂度。

可参考A中的8个7.5秒编辑窗口，但它不是官方模板，也不是通用的合法请求时长。实际生成段按后端能力选取并留裁切余量。若合同选24fps、精确60秒，最终目标是1440帧；转场重叠会减少总长，需另留handles。对白段不靠任意变速凑时长。

逐片原生音乐与统一master音轨是两条路线，分开验收。60秒master是编辑层资产，不能默认整条塞进单次Ref2VA音频参考。项目没有出镜对白需求时，先不增加精确口型这个变量。

## 6. 证据、判定与停止条件

每次生成至少保存：输入文件及hash、实际提交prompt/payload及hash、工作流与模型/后端版本、参考顺序与角色、seed与采样设置、任务ID/终态、原始视频及音频、实际帧数/尺寸/FPS/各音视频流时长、检查结果和后处理记录。私密字段脱敏。

服务不返回实际有效prompt时记`not_exposed`；客户端hash只证明发送端内容，不能证明服务端完整使用。

| 状态 | 使用条件 |
|---|---|
| `NOT_RUN` | 只有设计或静态检查，没有本轮生成结果 |
| `BLOCKED` | 缺材料、工具或能力；写明缺口，不算模型失败 |
| `PASS_NATIVE` | 未经修补的输出满足该项明确判据 |
| `PASS_POSTPROCESSED` | 经明确后处理满足成片要求，保留原生分数 |
| `FAIL` | 有原始证据证明指定合同未满足，注明失败层 |
| `INCONCLUSIVE` | 配置/原件不足或对照混淆，不能判断 |

任务返回completed、模型加载成功、文件可播放、提示词写fully_preserved，都不等于质量通过。原生片段、装配和证据完整性分开判。

出现以下情况应停在对应范围并说明原因：

- 缺Hub工具却要求执行8个Hub风格Skill：可以交前期包，不能假装生成器可用。
- 缺原始输出或参数：保留历史线索，停止确定根因的归因。
- 达到已定试验预算仍无稳定改善：报告未解决，不无限重试到挑出一条好片。
- 新测试不能改变制作路线或风险判断：不继续扩展无关用例。

特别注意：#51关闭只支持维护者承诺“下个版本修复”，不证明用户当前权重已修；#95附件作者明确未跑GPU且历史异常视频已删；#17各类声线workaround不是通用官方修复。具体证据以F和原链接核对，不照抄issue标题当事实。
